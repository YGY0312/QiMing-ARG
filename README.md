# QiMing 网页 ARG

当前公开测试版本：`0.3.0-test`。项目策划、设计与制作：**YGY0312**。

项目支持 GitHub 连接 Cloudflare Pages 自动部署、自定义域名和本地 `localStorage` 存档。公开测试反馈建议包含：出现问题的页面、操作步骤、预期结果、实际结果、浏览器与设备信息。移动端可运行，但复杂表格、文件查看器和测试控制台在桌面浏览器上体验更完整。

完整署名见 [CREDITS.md](CREDITS.md)，部署与测试环境配置见 [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md)。

## 公开测试工具

测试工具采用构建开关和访问开关双重保护：

- Cloudflare 构建环境设置 `VITE_ENABLE_TEST_TOOLS=true` 后，构建产物才包含测试控制台。
- 访问部署地址并增加 `?testmode=1` 才会显示右下角 `TEST` 入口；同一标签页刷新后继续有效。
- 点击控制台中的“退出测试模式”会清除当前标签页的测试状态并移除查询参数。
- 测试控制台可跳转剧情页面、切换账号、调整线索和章节状态、导入导出存档及生成反馈模板。它会改动浏览器本地存档，不能代替正常游玩验证。
- 正式发布时删除 Cloudflare 中的该环境变量或设为 `false`，重新部署即可让测试代码不进入生产包。

仓库只跟踪源代码和必要静态资源；`node_modules/`、`dist/`、`.pnpm-store/`、覆盖率、日志及本地环境文件均被排除，避免污染 GitHub 语言统计与仓库体积。

# 《退学证明》

《退学证明》是一款以虚构中国高中为背景的单人网页 ARG 调查游戏。当前版本已实现第一章《退学证明》、第二章《第十八个人》和第三章《值班记录》。玩家在游戏内伪浏览器中交叉核对学校官网、不同学生账号、历史附件与残留记录；所有域名、学校、人物和事件均为虚构。

## 当前实现

- React 19、TypeScript 严格模式、Vite 与原生 CSS。
- 固定学校官网主标签和可多开的学生系统标签；网址、历史、登录会话和文件窗口按标签独立保存。
- 林默、周寻两个剧情账号，随机验证码和动态保存账号列表。
- 第一、二章共用类型安全的线索、集中式事件、调查记录和常驻关键事实侧栏。
- 第二章官网站内搜索、删除页与旧索引残留；支持剧情关键词的本地数据匹配，不请求真实网络。
- 统一只读文件预览支持 TXT、DOC 文本、PDF 式资料、CSV 简表、18 座位座位表、隐藏行、批注恢复和文件属性。
- 第二章将班级名单历史、班级群历史、学籍历史缓存和门禁日志保留为学生系统页面；关键线索必须经过筛选、查看详情或手动比对才能确认。
- 第三章沿用学校官网和周寻账号，通过值班安排、实验楼访问记录及系统新闻的主动查询继续调查6月16日晚的异常。
- 文件不会触发现实设备下载，不创建 Blob URL，也不调用 `window.open`。
- `campus_arg_save_v5` 结构化存档，并继续迁移 v1、v2、v3、v4。

## 部署状态

- 支持 GitHub 连接 Cloudflare Pages 自动部署。
- 支持 Cloudflare Pages 预览部署和生产分支部署。
- 支持 `pages.dev` 地址与自定义域名。
- 推荐 Node.js 22.12.0；生产构建命令为 `npm run build`，输出目录为 `dist`。

完整设置参见 [Cloudflare Pages 部署说明](docs/DEPLOYMENT.md)。

## 章节与账号用途

第一章通过公开公告、照片与周寻的私人记录核对“退学”说法。第一章完成后，第二章自然开放，不强制弹出任务框。

第二章中，周寻账号提供检索记录、座位表、成绩资料，以及受权限控制的学籍历史和门禁查询；林默账号可从班级群迁移消息进入成员变更历史。林默不能直接读取周寻的私人调查文件，周寻也不能进入林默的班级群历史，项目没有沈栀登录账号。

第二章完成后，第三章《值班记录》自动开放。第三章继续保持账号权限隔离：实验楼访问调查资料只在周寻账号中出现，官网资料需要通过日期查询和记录核对主动确认。

官网搜索至少支持“沈栀”“高二三班”“高二（3）班”“实验楼”“实验器材整理”“写给未来的自己”“顾言”。搜索及页面内容均由本地配置驱动。

## 游戏内地址

- `www.qiming-high.edu.cn/news`：校园新闻及历史附件
- `www.qiming-high.edu.cn/notices`：通知公告

- `stu.qiming-high.edu.cn/login`：学生系统登录
- `stu.qiming-high.edu.cn/class-list`：当前与历史班级名单
- `stu.qiming-high.edu.cn/messages`：当前账号消息与草稿
- `stu.qiming-high.edu.cn/class-group-history`：林默账号的班级群历史
- `stu.qiming-high.edu.cn/student-status/cache`：周寻账号的学籍历史缓存
- `stu.qiming-high.edu.cn/access-query`：周寻账号的门禁日志查询

这些地址仅由游戏内部解析。

## v5 存档与迁移

当前键名为 `campus_arg_save_v5`。它保存标签与独立会话、已保存账号、侧栏状态、已访问页面、线索、事件、消息、解锁功能、章节完成时间、一次性异常标记，以及座位恢复、隐藏成绩行、文件属性和门禁比对项等交互状态。名单筛选条件、验证码、表单密码和临时输入不进入存档；旧 v5 中已发现的线索会直接映射为改版后相应交互的完成状态。

读取时按 v5 → v4 → v3 → v2 → v1 回退迁移。v4 的全部标签、历史、标签级账号会话、动态账号、第一章进度和侧栏状态会保留；第一章已完成的存档加载后会自然开放第二章，第二章已完成的 v5 存档会自然开放第三章。损坏数据安全回退，不要求旧玩家重玩已有章节。

## 图片与占位规则

剧情关键图片在开发早期可以使用CSS、SVG或简单占位图，但必须登记稳定资源ID、占位文件名、最终文件名、图片内容、剧情用途和必要视觉细节。正式发布前统一替换为经审核的AI生成或自制图片。

页面通过 `src/data/imageAssets.ts` 解析登记资源，热点使用 0–1 相对坐标。第二章座位表、征文和分组附件均采用 HTML/CSS 与结构化文本，不新增图片依赖。详情见 [图片替换计划](docs/IMAGE_REPLACEMENT_PLAN.md)。

## 当前限制与下一步

- 单本地存档槽，无后端、真实认证、云同步或真实网络请求。
- 伪浏览器只实现剧情所需的标签、地址和历史能力，不是完整浏览器。
- Office/PDF 文件是语义化预览，不解析真实二进制文档。
- 第一章实验室合照仍为 SVG 占位资源，正式发布前需审核替换。
- 第三章只确认6月16日晚存在值班与记录处理异常，不揭示完整管理员体系、最终幕后人物或当晚事件全貌。

下一阶段建议先进行完整章节可用性测试和移动端布局校准，再设计后续章节；继续沿用双站点、双账号、统一线索事件和虚拟文件架构。
